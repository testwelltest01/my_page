03 — 문제와 시스템

걷는 중에도 끊기면 안 되는 흐름

시각 정보 접근이 어려운 사용자에게 보행의 위험은 이름 붙은 객체로만 나타나지 않습니다. 같은 물체도 사람에겐 위험, 모델에겐 애매한 배경일 수 있죠.

WalkMate는 작은 버튼을 정확히 누르는 일반 앱과 다릅니다. 사용자는 걸으면서 목적지를 말하고, 안내를 듣고, 주변 위험을 파악해야 합니다. 그래서 음성·위치·카메라·안내가 하나의 흐름으로 동시에 동작하도록 설계했습니다.

위험 객체가 감지되면 별도 입력 없이도 위치·이미지·위험 정보가 백엔드로 전송되고, 관리자는 웹 대시보드에서 신고가 반복되는 지점을 공간적으로 확인합니다. 현장의 감지가 운영의 데이터로 이어지는 한 줄의 파이프라인입니다.

PILLAR 01 / AI ENGINEER

위험을 정의하고
모델로 만들다

YOLO11n · Ultralytics
PyTorch · TFLite
tfjs-tflite · WebAssembly

처음엔 점자블록 파손 탐지를 노렸지만, 파손이 심하면 형태 자체가 사라져 인식이 어려운 역설이 있었습니다. 그래서 탐지 대상을 더 일반적인 보행 위험 요소로 재정의하고, COCO 10개 클래스에 Roboflow 기반 볼라드·전동 킥보드를 더해 12개 클래스를 설계했습니다.

12 CLASSES — 위험도 매핑
car위험3 bus위험3 truck위험3 motorcycle위험3 bicycle위험3 kickboard위험3 person위험2 dog위험2 traffic light위험1 bollard위험1 stop sign위험1 bench위험1

감지 결과는 단순 객체명이 아니라 위험도(1–3)와 한국어 안내 문구로 변환되어, 사용자 TTS 안내와 신고 데이터 양쪽으로 이어집니다.

  • 01
    통합 단일 학습 전략

    순차 학습의 catastrophic forgetting과 라벨 노이즈 집중 위험을 피하기 위해 COCO·kickboard·bollard를 통합해 한 번에 학습했습니다.

  • 02
    자동 라벨링 보강

    원본 YOLO11n으로 COCO 계열 객체를 자동 라벨링해 기존 라벨에 append — 커스텀 데이터 안에서도 일반 객체 정보를 유지했습니다.

  • 03
    실험으로 모델 선택

    baseline·adamw_cos·heavy_aug를 비교해, 모든 핵심 지표에서 앞선 baseline을 앱 탑재 모델로 확정했습니다.

  • 04
    온디바이스 변환

    best.pt → ONNX → SavedModel → TFLite float32. 출력 [1,16,8400]을 YoloParser가 4 bbox + 12 score로 후처리(conf 0.30 / NMS 0.50).

PILLAR 02 / BACKEND

현장의 신고를
안전하게 받아내다

FastAPI · Uvicorn
SQLAlchemy · PostGIS
AWS S3(boto3) · TMAP

WebView 앱은 DB 비밀번호·AWS 키·TMAP 키 같은 민감한 값을 들고 있으면 안 됩니다. 백엔드는 앱과 데이터 사이의 보안 경계가 되어, 신고만 받고 이미지 저장·좌표 저장·관리자 처리·경로 프록시를 모두 담당합니다.

API SURFACE
  • GET
    /health
    서버 기동 여부 확인
  • POST
    /api/v1/reports/
    위험 신고 생성 · S3 업로드 · DB 저장 (multipart)
  • POST
    /api/v1/navigation/path
    TMAP 보행자 경로 프록시
  • GET
    /api/v1/reports/
    관리자 신고 목록 · pagination
  • PATCH
    /api/v1/reports/{id}
    처리 상태 변경 (new · processing · done)
  • DELETE
    /api/v1/reports/{id}
    물리 삭제 대신 숨김 처리
  • 01
    저장소 분리 설계

    이미지는 AWS S3에 올리고 DB에는 URL만. 메타데이터와 바이너리를 각각 적합한 저장소로 분리했습니다.

  • 02
    PostGIS 공간 좌표

    ST_MakePoint(lon, lat)로 geometry 저장, 조회 시 ST_Y/ST_X로 복원 — 공간 검색과 지도 표시를 동시에 만족.

  • 03
    계층 분리 구조

    endpoint · crud · service · core로 책임을 나눠, S3 업로드와 DB INSERT의 실패 지점을 추적하기 쉽게 구성.

  • 04
    안정성 장치

    pool_pre_ping, INSERT 실패 시 rollback, 환경 변수 누락 시 기동 단계 차단 등 예외 흐름을 명시.

이미지 저장 — AWS S3

신고 이미지는 바이너리 파일입니다. DB에 직접 넣으면 관리·비용·접근 경로가 불안정해지므로, 이미지는 S3에, 메타데이터는 PostgreSQL에 분리 저장했습니다.

다음을 압니다

핵심 흐름을 실제 앱·API·DB·S3·관리자 UI까지 연결했습니다. 운영 수준으로 가기 위해 무엇이 남았는지도 분명히 알고 있습니다.

DATA

라벨로 정의되지 않는 위험

고정 클래스 객체탐지만으로는 한계가 있습니다. 실사용 프레임 수집과 흔들림·야간·저조도 augmentation, 장면을 이해하는 VLM 접근을 검토합니다.

RUNTIME

WebView 추론 비용

iPhone WebView의 tfjs-tflite 추론은 발열·지연이 생길 수 있어, 네이티브 추론·Core ML·서버 추론과의 비교가 필요합니다.

SECURITY

권한과 RLS 설계

현재 Supabase RLS가 꺼져 있고 관리자 인증이 없습니다. 운영 전 인증·권한 정책과 데이터 접근 책임 정리가 우선입니다.

ACCESS

접근성 현장 검증

VoiceOver, 이어폰, 야외 소음, 화면 잠금, GPS 약한 환경 등 접근성 중심의 실사용 테스트를 더 쌓아야 합니다.
